# Разделение интерфейса и бизнес-логики

## Текущее состояние

- `main.py` — содержит бизнес-логику RSA (назван неудачно, но функционально это модуль логики)
- `gui.py` — GUI на tkinter, импортирует функции из `main.py`
- Проблемы: нет чёткого разделения модулей, `main.py` назван неудачно, GUI напрямую вызывает функции без абстракции

## План

### 1. Переименовать `main.py` → `rsa_crypto.py`

Бизнес-логика RSA переезжает в отдельный модуль `rsa_crypto.py`:
- `CipherError` — кастомное исключение
- `is_prime_miller_rabin(n, k)` — проверка простоты
- `generate_prime(bits)` — генерация простого числа
- `generate_keys(p, q)` → `(e, n, d)` — генерация RSA-ключей
- `encrypt(text, e, n)` → `list[int]` — шифрование
- `decrypt(ciphertext, d, n)` → `str` — дешифрование
- Вспомогательные: `extended_gcd`, `mod_inverse`, `_text_to_bytes_blocks`, `_blocks_to_text`

### 2. Обновить `gui.py`

GUI остаётся в `gui.py`, но:
- Импортирует из `rsa_crypto` вместо `main`
- Класс `CipherApp` остаётся как есть — он уже инкапсулирует UI
- Обработчики кнопок (`do_encrypt`, `do_decrypt`, `generate_primes`) остаются в классе — это часть UI-логики, они вызывают функции из `rsa_crypto`

### 3. Структура проекта после изменений
