# SOLID Refactoring Plan — KostyaBank ATM

## Текущие нарушения SOLID

### S — Single Responsibility
| Класс | Нарушение | Решение |
|-------|-----------|---------|
| `CardStorage` | Бизнес-логика + Excel I/O | Вынести Excel I/O в `ICardStorageRepository` |
| `MoneyStorage` | Бизнес-логика + Excel I/O | Вынести Excel I/O в `IMoneyStorageRepository` |
| `Printer` | Форматирование чека + запись в файл | Разделить на `IReceiptFormatter` + `IReceiptWriter` |
| `Card` | Модель + валидация (`IsValid`, `ErrorMessage`) | Вынести в `ICardValidator` |
| `Money` | Модель + валидация номиналов | Вынести в `INominalValidator` |
| `Computer` | Чтение Excel (дублирует `CardStorage`) | Использовать общий `IExcelReader` |
| `CardEntryViewModel` | Создаёт `Computer` и `CardStorage` напрямую | Внедрить через конструктор (DI) |

### O — Open/Closed
| Класс | Нарушение | Решение |
|-------|-----------|---------|
| `AppViewModel` | Жёстко привязан к конкретным ViewModel, все навигационные методы в одном классе | `INavigationService` с методами-стратегиями |
| `Printer` | Новые типы документов = модификация класса | `IReceiptFormatter` — новые типы = новые реализации |

### I — Interface Segregation
| Нарушение | Решение |
|-----------|---------|
| `CardEntryViewModel` создаёт зависимости сам | `ICardRepository`, `ICardStorageRepository`, `IExcelReader` — сегрегированные интерфейсы |
| `SimpleCommand` определён в `MainMenuViewModel` | Переместить в отдельный файл `SimpleCommand.cs` |

### L — Liskov Substitution
| Нарушение | Решение |
|-----------|---------|
| `Money` — один класс для модели ввода (ViewModel) и данных (хранилище) | Разделить: `MoneyDenomination` (данные) + использовать ViewModel-модели отдельно |

### D — Dependency Inversion
| Нарушение | Решение |
|-----------|---------|
| Все ViewModel зависят от конкретных классов (`new Computer()`, `new CardStorage()`, `new Printer()`) | Зависить от интерфейсов; `AppViewModel` → Composition Root |

## Архитектура после рефакторинга

```
Models/
  Card.cs                  (чистая POCO, без валидации)
  MoneyDenomination.cs     (данные номиналов: Nominal, Count)
  CardValidationResult.cs  (результат валидации)

Services/                  (новый слой)
  ExcelReader.cs           (общий парсер Excel: Card/Money rows)
  CardValidator.cs         (валидация номера карты, PIN)
  NominalValidator.cs      (валидация номиналов купюр)
  ReceiptFormatter.cs      (форматирование текста чека/справки)
  ReceiptWriter.cs         (запись чека в файл)

Repositories/              (новый слой)
  ICardRepository.cs       (GetCardByNumber — чтение из comp.xlsx)
  CardRepository.cs
  ICardStorageRepository.cs (CRUD + Excel — card_storage.xlsx)
  CardStorageRepository.cs
  IMoneyStorageRepository.cs (CRUD + Excel — money_storage.xlsx)
  MoneyStorageRepository.cs

ViewModels/
  SimpleCommand.cs         (вынесено из MainMenuViewModel)
  BaseViewModel.cs         (без изменений)
  CardEntryViewModel.cs    (зависимости через DI)
  MainMenuViewModel.cs     (убран SimpleCommand)
  CardFormViewModel.cs     (без изменений)
  GetFormViewModel.cs      (зависимости через DI)
  ShowFormViewModel.cs     (зависимости через DI)
  ServiceViewModel.cs      (исправлены конструкторы)
  MoneyStorageViewModel.cs (зависимости через DI)
  CardStorageViewModel.cs  (зависимости через DI)
  AppViewModel.cs          (Composition Root — создаёт всё, навигация)
```

## Пошаговый план реализации

### Шаг 1: Создать новые интерфейсы
- `ICardRepository` — `Card? GetCardByNumber(string cardNumber)`
- `ICardStorageRepository` — `IEnumerable<Card> GetCards()`, `bool AddCard(Card)`, `bool RemoveCard(string)`, `void Clear()`
- `IMoneyStorageRepository` — `IEnumerable<int> GetNominals()`, `int GetCount(int nominal)`, `void AddMoney(int nominal, int count)`, `bool RemoveMoney(int nominal, int count)`, `void Clear()`, `int SumMoney()`
- `IExcelReader` — `List<Card> ReadCards(string filePath)`, `Dictionary<int, int> ReadMoney(string filePath)`
- `ICardValidator` — `CardValidationResult Validate(string cardNumber, string pinCode)`
- `INominalValidator` — `bool IsValidNominal(int amount)`
- `IReceiptFormatter` — `string FormatWithdrawReceipt(...)`, `string FormatBalanceReceipt(...)`
- `IReceiptWriter` — `string WriteToFile(string content, string fileName)`

### Шаг 2: Создать классы валидации (Services)
- `CardValidator` — реализует `ICardValidator`
- `NominalValidator` — реализует `INominalValidator`

### Шаг 3: Создать ExcelReader (Services)
- `ExcelReader` — реализует `IExcelReader`
- Убрать дублирование Excel-кода из `Computer`, `CardStorage`, `MoneyStorage`

### Шаг 4: Создать репозитории (Repositories)
- `CardRepository` — использует `IExcelReader` для чтения из `comp.xlsx`
- `CardStorageRepository` — использует `IExcelReader` для работы с `card_storage.xlsx`
- `MoneyStorageRepository` — использует `IExcelReader` для работы с `money_storage.xlsx`

### Шаг 5: Разделить Printer (Services)
- `ReceiptFormatter` — реализует `IReceiptFormatter` (только текст)
- `ReceiptWriter` — реализует `IReceiptWriter` (только запись в файл)

### Шаг 6: Модели
- `Card` — убрать `IsValid` и `ErrorMessage`, оставить только POCO
- `Money` — переименовать в `MoneyDenomination` (данные), ViewModel-логику убрать
- Создать `CardValidationResult` (IsSuccess, ErrorMessage)

### Шаг 7: ViewModels
- Переместить `SimpleCommand` в отдельный файл
- `CardEntryViewModel` — зависимости через DI (`ICardRepository`, `ICardStorageRepository`, `ICardValidator`)
- `GetFormViewModel` — зависимости через DI (`IMoneyStorageRepository`, `IReceiptFormatter`, `IReceiptWriter`)
- `ShowFormViewModel` — зависимости через DI (`IReceiptFormatter`, `IReceiptWriter`)
- `ServiceViewModel` — убрать двойные конструкторы, использовать DI
- `MoneyStorageViewModel` — использовать `IMoneyStorageRepository`
- `CardStorageViewModel` — использовать `ICardStorageRepository`
- `AppViewModel` — Composition Root: создаёт все зависимости, навигация через методы

### Шаг 8: Обновить App.xaml.cs / XAML
- Убедиться, что `AppViewModel` создаётся в `App.xaml.cs` как корень DI
- Проверить, что все DataBindings работают с новыми ViewModel

### Шаг 9: Сборка и проверка
- `dotnet build` — убедиться, что нет ошибок компиляции
- Проверить, что приложение запускается

## Ключевые изменения для пользователя (функционально)
- **Нет изменений UI** — все экраны остаются те же
- **Нет изменений формата Excel** — файлы читаются/записываются так же
- **Логика банкомата** — та же (ввод карты, PIN, снятие, баланс, сервис)
- **Чек/справка** — тот же формат вывода

## Риски
1. `Money` используется в `ObservableCollection<Money>` в XAML — нужно убедиться, что свойства (`Amount`, `Count`, `Subtotal`) остаются
2. EPPlus лицензия — `LicenseContext.NonCommercial` должен устанавливаться один раз (перенести в `App.xaml.cs`)
3. `Card.Balance` меняется в `GetFormViewModel` — модель Card должна оставаться мутируемой
