# SOLID Refactoring Plan for KostyaBank

## Goal
Refactor the WPF ATM application to comply with all five SOLID principles.

## Current Architecture Analysis

### SOLID Violations Found

| Principle | Violation | Location |
|-----------|-----------|----------|
| **SRP** | Excel I/O duplicated in 3 classes | `Computer`, `CardStorage`, `MoneyStorage` |
| **SRP** | `AppViewModel` handles navigation + DI + exit logic | `AppViewModel` |
| **SRP** | `Printer` formats AND writes to disk | `Printer` |
| **SRP** | `Card` has data + validation logic | `Card` |
| **SRP** | `Money` mixes model data with UI concerns | `Money` |
| **SRP** | `Log` helper mixed into `App.xaml.cs` | `App.xaml.cs` |
| **SRP** | `SimpleCommand` nested inside `MainMenuViewModel` | `MainMenuViewModel` |
| **OCP** | Adding a new screen requires modifying `AppViewModel` | `AppViewModel` |
| **OCP** | Adding new document types requires modifying `Printer` | `Printer` |
| **OCP** | Hardcoded validation in `CardEntryViewModel` | `CardEntryViewModel` |
| **LSP** | `ServiceViewModel` has two constructors with different semantics | `ServiceViewModel` |
| **ISP** | No interfaces at all — everything coupled to concrete classes | Entire codebase |
| **DIP** | ViewModels create dependencies with `new` | `CardEntryViewModel`, `GetFormViewModel`, `ShowFormViewModel`, `CardStorageViewModel`, `AppViewModel` |

## Refactoring Steps

### Step 1: Extract Interfaces (ISP + DIP)

Create `Interfaces/` folder with:

1. **`ICardRepository`** — abstracts card data access
   ```csharp
   interface ICardRepository
   {
       Card? GetByNumber(string cardNumber);
       IEnumerable<Card> GetAll();
       bool Add(Card card);
       bool Remove(string cardNumber);
       void Clear();
       int Count { get; }
   }
   ```

2. **`IMoneyRepository`** — abstracts money storage access
   ```csharp
   interface IMoneyRepository
   {
       IEnumerable<Money> GetMoneyEntries();
       int SumMoney();
       int TakeMoney(int amount);
       void AddMoney(int nominal, int count);
       bool RemoveMoney(int nominal, int count);
       int GetCountByNominal(int nominal);
       void Clear();
   }
   ```

3. **`IDocumentFormatter`** — abstracts document generation
   ```csharp
   interface IDocumentFormatter
   {
       string FormatWithdrawReceipt(decimal amount, Card card, DateTime date);
       string FormatBalanceStatement(Card card, DateTime date);
   }
   ```

4. **`IDocumentWriter`** — abstracts file writing
   ```csharp
   interface IDocumentWriter
   {
       string Save(string content, string baseFileName, DateTime date);
   }
   ```

5. **`ILogger`** — abstracts logging
   ```csharp
   interface ILogger
   {
       void Write(string message);
   }
   ```

6. **`INavigationService`** — abstracts view switching
   ```csharp
   interface INavigationService
   {
       void NavigateToCardEntry();
       void NavigateToMainMenu(Card card);
       void NavigateToGetForm(Card card);
       void NavigateToShowForm(Card card);
       void NavigateToServiceView();
       void NavigateToMoneyStorage();
       void NavigateToCardStorage();
   }
   ```

### Step 2: Create Repository Implementations (SRP)

1. **`ExcelCardRepository`** — implements `ICardRepository`, handles Excel I/O for cards
   - Extracts the Excel loading/saving logic from `CardStorage`
   - `CardStorage` class is removed (its functionality moves here)

2. **`ExcelMoneyRepository`** — implements `IMoneyRepository`, handles Excel I/O for money
   - Extracts the Excel loading/saving logic from `MoneyStorage`
   - `MoneyStorage` class is removed (its functionality moves here)

3. **`ExcelComputerRepository`** — implements `ICardRepository` (read-only) OR create a separate `ICardLookup` interface
   - Actually, `Computer` serves a different purpose (lookup from `comp.xlsx`). Better to create:
   - **`ICardLookup`** — read-only card lookup
   - **`ExcelCardLookup`** — implements it, reads from `comp.xlsx`

### Step 3: Create Document Services (SRP + OCP)

1. **`ReceiptFormatter`** — implements `IDocumentFormatter`
   - Extracts formatting logic from `Printer`
   - Open for extension: new formatters can be added without modifying existing code

2. **`FileDocumentWriter`** — implements `IDocumentWriter`
   - Extracts file writing logic from `Printer`
   - Can be swapped for `CloudDocumentWriter`, `PdfDocumentWriter`, etc.

3. **`Printer`** — becomes a thin facade that uses `IDocumentFormatter` + `IDocumentWriter`
   ```csharp
   public class Printer : IPrinter
   {
       private readonly IDocumentFormatter _formatter;
       private readonly IDocumentWriter _writer;
       // constructor injection
   }
   ```

### Step 4: Create Logger Service (SRP)

1. **`FileLogger`** — implements `ILogger`
   - Extracts `Log` static class from `App.xaml.cs`
   - Can be swapped for `ConsoleLogger`, `NLogLogger`, etc.

### Step 5: Refactor AppViewModel (SRP + DIP)

`AppViewModel` becomes a pure navigation coordinator:

1. Remove direct `new` calls for `Computer`, `CardStorage`, `MoneyStorage`
2. Accept `ICardLookup`, `ICardRepository`, `IMoneyRepository`, `INavigationService` via constructor
3. Navigation methods become simple wrapper calls to `INavigationService`
4. Remove `ExitApp` — move to a dedicated `IExitService` or handle in `MainWindow`
5. Remove `MoneyStorage` property — inject `IMoneyRepository` instead

```csharp
public class AppViewModel : BaseViewModel, INavigationService
{
    private readonly ICardLookup _cardLookup;
    private readonly ICardRepository _cardRepository;
    private readonly IMoneyRepository _moneyRepository;
    private readonly ILogger _logger;

    // Navigation state
    public object CurrentView { get; private set; }

    public AppViewModel(ICardLookup cardLookup, ICardRepository cardRepository, 
                        IMoneyRepository moneyRepository, ILogger logger)
    {
        _cardLookup = cardLookup;
        _cardRepository = cardRepository;
        _moneyRepository = moneyRepository;
        _logger = logger;
        CurrentView = new CardEntryViewModel(this);
    }

    // INavigationService implementation
    public void NavigateToCardEntry() => CurrentView = new CardEntryViewModel(this);
    public void NavigateToMainMenu(Card card) => CurrentView = new MainMenuViewModel(card, this);
    // ... etc
}
```

### Step 6: Refactor ViewModels (DIP)

All ViewModels that create dependencies will accept them via constructor:

1. **`CardEntryViewModel`** — accepts `ICardLookup`, `ICardRepository`, `INavigationService`
2. **`GetFormViewModel`** — accepts `IMoneyRepository`, `IDocumentFormatter`, `IDocumentWriter`
3. **`ShowFormViewModel`** — accepts `IDocumentFormatter`, `IDocumentWriter`
4. **`CardStorageViewModel`** — accepts `ICardRepository`, `INavigationService`
5. **`MoneyStorageViewModel`** — accepts `IMoneyRepository`, `INavigationService`
6. **`MainMenuViewModel`** — accepts `INavigationService`

### Step 7: Fix LSP

1. Remove the dual-constructor pattern from `ServiceViewModel`
2. Make `ServiceViewModel` only work with a card (required parameter)
3. If service view is needed without a card, create `AdminServiceViewModel` or handle in navigation

### Step 8: Extract SimpleCommand (SRP)

Move `SimpleCommand` from `MainMenuViewModel` to its own file `SimpleCommand.cs` in the root or ViewModels folder.

### Step 9: Refactor Card and Money Models (SRP)

1. **`Card`** — keep only data properties. Move validation to a separate `CardValidator` class implementing `IValidator<Card>`
2. **`Money`** — keep only data. Move `PossibleAmounts` to a configuration class or `IMoneyConfig` interface

### Step 10: Wire Up in App.xaml.cs (DIP)

Create a simple DI registration in `OnStartup`:

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    var logger = new FileLogger();
    var cardLookup = new ExcelCardLookup();
    var cardRepository = new ExcelCardRepository();
    var moneyRepository = new ExcelMoneyRepository();
    var formatter = new ReceiptFormatter();
    var writer = new FileDocumentWriter();
    var printer = new Printer(formatter, writer);
    
    var appViewModel = new AppViewModel(cardLookup, cardRepository, moneyRepository, logger);
    var mainWindow = new MainWindow();
    mainWindow.DataContext = appViewModel;
    mainWindow.Show();
}
```

## Implementation Order

1. **Step 8** — Extract `SimpleCommand` (no dependencies, safe first step)
2. **Step 10** — Extract `ILogger` / `FileLogger` (standalone, no existing class uses it yet)
3. **Step 1** — Create all interfaces
4. **Step 2** — Create repository implementations
5. **Step 3** — Create document services
6. **Step 4** — Already done in step 10
7. **Step 7** — Fix `ServiceViewModel` LSP issue
8. **Step 9** — Refactor `Card` and `Money` models
9. **Step 5** — Refactor `AppViewModel`
10. **Step 6** — Refactor all ViewModels
11. **Step 10** — Wire up DI in `App.xaml.cs`

---

## Risk Assessment

- **Low risk**: Extracting `SimpleCommand`, creating interfaces, creating new service classes
- **Medium risk**: Refactoring ViewModels to accept DI — need to ensure XAML bindings still work
- **Low risk**: Refactoring `AppViewModel` — it's the central coordinator

## What Stays the Same

- All XAML files (`*.xaml`) — bindings use property names, not types
- `BaseViewModel` — already follows good patterns
- `CardFormViewModel` — already a good abstract base class
- `MainWindow.xaml.cs` — keyboard handling can stay, or be extracted to a behavior
